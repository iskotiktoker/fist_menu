# ALTYN — меню и управление для Netlify

Готовый проект для существующей связки GitHub → Netlify. Клиентское меню, серверные функции и общие настройки хранятся в одном репозитории. Локальный архив не меняет уже опубликованный сайт.

## Роли

- **Администратор:** видит блюда и отмечает «В наличии / Закончилось».
- **Владелец:** также меняет цены, названия, описания, фото, состав, аллергены и остроту; добавляет блюда и скрывает/возвращает их; меняет контакты, график и тарифы; создаёт администраторов, отключает доступ и сбрасывает пароли; смотрит последние 200 изменений и скачивает копию меню.

Права проверяются сервером. Скрытие кнопок в браузере не используется как защита. Открытой регистрации нет.

Панель: **https://ВАШ-САЙТ/admin** (также работает `/admin.html`).

## Как обновить существующий сайт

1. Сохраните копию текущего репозитория.
2. Загрузите **содержимое этой папки** в корень репозитория GitHub: `public`, `lib`, `netlify`, `scripts`, `tests`, `package.json`, `netlify.toml` и `.gitignore`.
3. В Netlify оставьте подключение к тому же репозиторию. Базовая папка проекта должна указывать на папку с `package.json` и `netlify.toml`.
4. Файл `netlify.toml` задаёт сборку `npm run build`, публикацию `dist` и функции `netlify/functions`. Netlify устанавливает библиотеку из `package.json`.
5. Настройте вход владельца по инструкции ниже и запустите новый deploy.
6. Откройте сайт и `/admin`. Проверьте вход, наличие и цены на телефоне.

**Не загружайте только папку `dist` через ручной drag-and-drop.** Такой способ не устанавливает и не собирает серверные функции. Здесь нужен deploy через подключённый GitHub-репозиторий или Netlify CLI с установкой зависимостей.

Текущий статический сайт при этом заменяется проектом с серверной частью. Никакого отдельного VPS не требуется.

## Первый вход владельца

Пароль не задан заранее. Секреты нельзя помещать в GitHub и публичные JS-файлы.

1. На своём компьютере откройте терминал в этой папке.
2. Запустите:

   ```sh
   python3 scripts/create-owner.py
   ```

3. Придумайте пароль от 12 символов и повторите его. Ввод скрыт; скрипт не сохраняет и не печатает пароль.
4. Скрипт покажет две переменные. Добавьте их в **переменные окружения сайта Netlify**, с областью **Functions**:
   - `OWNER_LOGIN`: например, `founder`;
   - `OWNER_PASSWORD_HASH`: полная строка, которую вывел скрипт.
5. Выполните новый deploy, чтобы функции получили переменные.
6. Откройте `/admin`, введите выбранный логин и свой пароль.

В панели «Сотрудники» можно создать отдельных администраторов. Не передавайте им пароль владельца.

Для смены или восстановления пароля владельца снова запустите скрипт, замените `OWNER_PASSWORD_HASH` в Netlify и выполните новый deploy. Старые сессии владельца перестанут действовать. Хеш нельзя добавлять в `netlify.toml`: там секреты не защищены, а переменные не передаются в функции так же, как переменные Functions.

## Где сохраняются изменения

Используется site-wide хранилище **Netlify Blobs**, имя `altyn-restaurant-v1`, с сильной согласованностью. Доступ к нему получают серверные функции; ключи доступа не попадают в браузер.

Меню, настройки, администраторы и журнал сохраняются в документе `state`. Изменения принимаются только для актуальной версии документа. Одновременная устаревшая запись возвращает ошибку и просит обновить панель.

Вход хранится в серверной сессии на 8 часов. Cookie — HttpOnly, Secure для HTTPS и SameSite=Strict. Изменения требуют проверки Origin и CSRF-токена. Пароли сотрудников хранятся только как хеши scrypt; секрет владельца — в Netlify Functions environment. Отключение сотрудника или смена его пароля отзывает старые сессии.

Существующее меню **не сбрасывается при новом deploy**. `lib/menu-seed.json` используется только при первом обращении к пустому хранилищу. После этого меняйте меню через панель. Не удаляйте хранилище Blobs без сохранённой копии нужных данных.

Клиентское меню получает актуальные данные при открытии и обновляет их каждые 30 секунд, пока страница видима. При изменении цены или наличия показывает уведомление. Если обновление недоступно, просит подтвердить цены и наличие в WhatsApp.

## Файлы

- `public/`: меню и интерфейс управления, разрешённые к публикации.
- `lib/service.mjs`: серверная проверка прав и обработка действий.
- `lib/security.mjs`: хеширование и проверка паролей.
- `lib/menu-seed.json`: первоначальные 64 блюда и настройки.
- `netlify/functions/`: HTTP API и отдельная функция входа с ограничением частоты запросов.
- `scripts/`: сборка и создание хеша владельца.
- `tests/`: проверки серверных прав и сохранения данных.

При сборке только `public/` копируется в `dist/`. Файлы сервера, seed и секреты не публикуются как статические файлы. Не меняйте publish directory на корень репозитория.

## Проверки

```sh
npm test
npm run build
```

Проверки сервера запускаются на Node.js без внешних облачных аккаунтов с подменяемым хранилищем. Проверены:

- вход и отсутствие стандартного пароля;
- защищённая cookie, Origin, CSRF и срок сессии;
- запрет администратору менять цены, настройки и учётные записи;
- изменение наличия, цены, добавление и скрытие блюд;
- сброс пароля и отзыв доступа;
- тарифы, журнал и защита от одновременной перезаписи;
- отсутствие паролей и хешей в публичных ответах.

Также программно проверены запуск клиентского меню, расчёты, WhatsApp, переводы и график работы. Тестовый deploy опубликован: https://deploy-preview-1--f1rstmenu.netlify.app . Реальный API Netlify вернул 64 блюда и расписание; экран входа доступен. В браузере на ширине 390 px проверены отсутствие горизонтальной прокрутки, корзина, тариф 200 сом и блокировка доставки вне часов приёма. Авторизованные операции в облаке пока не проверены: OWNER_LOGIN и OWNER_PASSWORD_HASH ещё не настроены. SDK Netlify установлен, его импорты и сборка серверных функций проверены локально. Проверки прав используют модель хранилища; соединение с реальным Blobs проверяется после публикации в аккаунте Netlify. Зависимости зафиксированы в package-lock.json.
